# Canonical Kalah V1 Storeless Recurrence

Let `D = s0 - s1` be the existing store margin and let `p` contain only the twelve active pits. Define `F(p, q)` as the final player-zero margin generated by those active stones when player `q` moves. For an action `a`, the standalone transition returns child pits `p'`, child player `q'`, signed immediate store change `d(a)`, and, when terminal, the signed sweep `w(a)` already included in `d(a)`.

For a terminal state, `F(p, q) = sum(p[0:6]) - sum(p[6:12])`. Otherwise:

```text
F(p, 0) = max_a (d(a) + (terminal(a) ? 0 : F(p', q')))
F(p, 1) = min_a (d(a) + (terminal(a) ? 0 : F(p', q')))
```

The complete-state value is `V(p, s0, s1, q) = D + F(p, q)`. Every legal child has `D' = D + d(a)`, so induction on the recurrence gives `V(child) = D + d(a) + F(child pits, child player)`. Thus every action value differs from its storeless value by the same `D`; adding a constant preserves the complete maximizing or minimizing action set. For a terminal state, adding `D` to the active-stone sweep has the same result. This also proves that changing stores from `(s0, s1)` to `(s0 + x, s1 + y)` shifts every final value by `x - y` and cannot alter optimal actions.

`kalah_v1` terminality is based only on the resulting current player having no legal move. Therefore a one-sided board is playable when its non-empty side moves and is terminal when its empty side moves. Terminal sweep credits the opposite side, exactly as the canonical rules engine does.

## Dense Layout And Bounds

Tier `t` contains `C(t + 11, 11)` weak compositions in lexicographic pit order and two separately indexed players, at offsets `2 * rank(pits) + player`. Cumulatively through `T`, the state count is `2 * C(T + 12, 12)`, by the hockey-stick identity. Active stones are conserved until entering a store or capture; no final store contribution from active stones can exceed `t` in magnitude. Hence `F` is in `[-t, t]`; signed `int8` safely represents all tiers through 20, and `-128` cannot be a valid value.

## Format

`KVTB1` schema 1 is a little-endian native feasibility format: magic, schema, `kalah_v1` rules id, maximum tier, one-byte signed value encoding, `-128` sentinel, endianness marker, cumulative state count, FNV-1a-64 payload checksum, then tier-ordered payload bytes. Tier offsets are deterministically reconstructed from the combinatorial counts. The runner additionally records SHA-256, generator commit, and fixed generation parameters in results JSON.
